# RC4: совместимость с опубликованной веткой Netlify

## Причина отдельной редакции

При адресном HTTP-чтении 16.11.2026 выяснилось, что сайт https://incandescent-clafoutis-f22c0a.netlify.app/ и исходный архив `gta-ege-rc3-20261115-dist.zip` используют одинаковые `contentEdition: 14` и storage version 4, но разные ID вопросов и разные билеты. В опубликованной ветке есть также собственный набор редакции 13.

Новый экзамен получает `CONTENT_EDITION = 15`. Storage version остаётся 4. `buildTicket(seed, 13)` и `buildTicket(seed, 14)` из исходного RC3 не изменены. Билет 15 содержит тот же утверждённый набор RC3, кроме отдельного ID хронологии `v15-b-release-order`: теперь пять игр выбираются последовательными нажатиями.

## Восстановление сохранённых попыток

`netlify-legacy-content.js` добавляет десять исторических записей с исходными ID:

| ID | Источник / содержание | Правильный ключ |
| --- | --- | --- |
| `v13-a-1` | Клон `v12-a-1`, трюк на BMX | `0` |
| `v13-a-2` | Клон `v6-a-tommy`, 6 баллов | `tommy` |
| `v13-a-3` | Клон `v12-a-2` с кадром Нико | `0` |
| `v13-a-4` | Клон `v12-a-3` с кадром Франклина | `1` |
| `v13-b-1` | Клон `v12-b-1`, I Ran | `vicecity` |
| `v13-b-2` | Клон `v12-b-2`, Vladivostok FM | `0` |
| `v13-b-3` | Клон `v12-b-3`, APC | `0` |
| `v13-b-4` | Четыре игры по выходу | `iii, vc, sa, iv` |
| `v13-b-5` | Штат Леонида | `leonida` |
| `v14-a-release` | Дата в историческом анонсе | `r19` |

Клоны создаются после основной подготовки банка, потому что их источники `v12-*` появляются внутри `prepareBank()`. Модуль не меняет переданный банк, не разделяет с ним изменяемые массивы и не заменяет существующие вопросы. Повторный вызов с уже добавленными идентичными записями возвращает пустой массив. Несовпадение существующей записи с историческим ID вызывает явную ошибку вместо подмены ключа.

Подобные по смыслу вопросы нельзя объединять по имени персонажа. Например, исторический вопрос о Белликах принимает `0`, а запись исходного RC3 — `cousins`. Вопрос о Франклине в старой ветке спрашивает, кто имеет способность, и принимает `1`; запись исходного RC3 спрашивает, какая это способность, и принимает `driving`.

### Интеграция в приложение

Подключить модуль перед `app.js`:

```html
<script defer src="netlify-legacy-content.js"></script>
```

После основного `prepareBank()` и до создания `byId`:

```js
bank = E.prepareBank(originalQuestions, currentExtraQuestions);
bank.push(...window.GTAExamNetlifyLegacyQuestions.create(bank));
byId = Object.fromEntries(bank.map(question => [question.id, question]));
```

Восстанавливать исходные `saved.questionIds`, `answers` и `drafts`. Не пересобирать сохранённый билет через `buildTicket(saved.variant, saved.contentEdition)`: номер редакции у двух исторических веток совпал, а состав — нет. В проверке/определении редакции попытки и при создании ссылки приложение должно разрешать значение 15. Новый `initialDraft()` для `orderMode: 'tap'` возвращает `[]`; UI добавляет/убирает только ID из `q.items` и разрешает отправку после `E.ready(q, draft)`.

Для двух исторических иллюстраций сохранены их исходные пути: `assets/rc2-cities.svg` и `assets/rc3-release.svg`. Эти SVG должны входить в готовый архив. Сеть для восстановления банка или оценки ответа не нужна.

## Дата релиза в старом билете

У `v14-a-release` оставлены варианты ответа, ключ `r19`, баллы и media metadata. Формулировка теперь явно историческая: «По анонсу, использованному в этом билете…». Объяснение относится к сохранённому анонсу. Поле `releasedPrompt` удалено. Таймер и автоматическая надпись «GTA VI вышла» не переносятся. Исторический ключ не является проверкой текущей даты выхода игры.

## Две механики хронологии

| Запись | Начальный ответ | Игры | Начисление |
| --- | --- | --- | --- |
| Netlify `v13-b-4` | `[]`, последовательные нажатия | `iii, vc, sa, iv` | 2 за позицию; максимум 8 |
| RC3 `v13-b-release-order` | Полная перемешанная последовательность | `iii, vicecity, sanandreas, iv, v` | 1 за позицию + 3 за весь порядок |
| RC4 `v15-b-release-order` | `[]`, последовательные нажатия | Те же пять игр и логотипы RC3 | Те же 1 за позицию + 3 за весь порядок |

Все три записи сосуществуют. Историческая запись RC3 не изменена. Короткий массив, дубликаты и неизвестные ID не принимаются как завершённый ответ.

## Ограничение старых ссылок

Ссылка только с `v14_вариант` или `edition=14` не содержит достаточно информации, чтобы различить два разных исторических билета. То же относится к редакции 13. В этой сборке такие ссылки сохраняют поведение исходного RC3. Точный билет пользователя из другой ветки восстанавливается по сохранённым `questionIds`. Новые ссылки получают редакцию 15, чтобы дальнейшие изменения не повторяли эту неоднозначность.

## Проверки

```sh
node --test tests/netlify-compat.test.cjs
```

8 проверок прошли. Девять полных legacy-объектов сверены с SHA-256, захваченными из реально прочитанного production `exam-engine.js` и совпавших базовых данных. Для исторического вопроса даты отдельно проверены все поля кроме намеренно изменённых формулировок. Проверены: отсутствие мутаций и подмены ключей; сериализация сохранённых live-билетов 13/14; неизменность полных RC3-билетов 13/14; новый default 15; сумма 100; разделы 24/40/36; порог 60; обе механики нажатий и валидность ответов.

Эти проверки подтверждают слой банка и оценки. Интеграционные тесты приложения отдельно проверяют подключение модуля, восстановление интерфейса и нажатия. Игровая логика, SCM и native-протокол этой совместимостью не изменены.
