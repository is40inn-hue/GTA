# RC2 — сохранение чтения кэша после отказа записи

## Наблюдение и границы диагноза

В браузере подготовка дошла до `0.9204828678741361`, затем DOM показал `data-state="unavailable"`. Для текущего manifest это 63 365 689 подтверждённых байт — 371 часть. Следующая часть: `vice-district/877b827ae7e2-od_hotels1.txd`, 417 792 байта. Её размер и SHA-256 локально совпадают с manifest.

Статус после ненулевого прогресса указывает на недоступность CacheStorage для подготовки. Лимиты очереди проверяются до первого скачивания; обычная сетевая ошибка или неверный SHA дали бы состояние повторной попытки. Однако по DOM нельзя определить, был ли это отказ квоты, таймаут или другая ошибка хранилища. Принудительное исчерпание квоты и изменение разрешений браузера не выполнялись.

## Изменение

`dist/native-assets.js` теперь различает возможность читать и записывать CacheStorage:

- Ошибка или таймаут `put` отключает дальнейшие записи и фоновую подготовку. Уже открытый кэш остаётся доступен для foreground-загрузки части С.
- `match`, чтение тела, `delete` и открытие кэша остаются ограничены таймаутом 1,5 секунды. Ошибка чтения отключает дальнейшие обращения к хранилищу, чтобы С могла продолжить загрузку через сеть.
- Повреждённый файл в кэше по-прежнему выявляется по размеру и SHA-256, удаляется и загружается заново. Это работает и после перехода к чтению без записи; прежняя отметка `verified` не заменяет повторную проверку bytes.
- Не менялись очередь А/Б, приоритет медиа, пауза при скрытии, handoff в С, manifest, ассеты или игровой движок.

`cachedStats()` сохраняет поле `available`: теперь оно означает, что доступны и чтение, и запись, то есть можно продолжать фоновую подготовку. Дополнительно возвращаются `readable`, `writable`, `cacheFailure`. Последнее содержит только `operation` и `name` из фиксированного списка безопасных имён ошибок; сообщения ошибок, URL и другие сведения не публикуются. Возвращается копия диагностического объекта.

При отказе записи ожидается, например:

```json
{
  "available": false,
  "readable": true,
  "writable": false,
  "cacheFailure": { "operation": "put", "name": "QuotaExceededError" }
}
```

Это пример диагностического формата, не утверждение о конкретной причине наблюдаемой остановки на 92%.

## Проверка

Команда: `node --test tests/native-preload.test.cjs`.

**41 проверка пройдена, 0 ошибок.** Новые регрессии воспроизводят отказ записи квоты, обычную ошибку записи и зависший `put`: первая часть успешно подготовлена, следующая не сохраняется, затем foreground получает первую из CacheStorage без повторного сетевого запроса. Затем сохранённые bytes намеренно повреждаются в тестовом хранилище: SHA-проверка отклоняет их, и загрузчик получает корректную копию через сеть без повторной попытки записи.

Сохранены проверки ограниченного ожидания `open/match/body/delete`, отмены запросов, повторного использования общего кэша, перехода А → Б, скрытия страницы и приоритета медиа. Эти проверки используют тестовое хранилище, управляемые таймеры и ответы сети. Реальная причина браузерного отказа на 92% не установлена; WASM/GPU этим изменением не проверялись.
